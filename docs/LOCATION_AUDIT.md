# MapNews 오프라인 지역 추출·지도 표시율 감사

## 기준

- 저장 파일: main의 \`news_results.json\` 339개 기존 기사
- 좌표: 저장소에 포함된 \`map_visualization/.geocode_cache.json\` 120개 키
- PR #15의 마지막 CI(Linux/Windows): 별도 새 결과 파일 생성, 좌표 17/339개
- **기존 정규식만 재현한 수치:** 제목에서 82/339개 지역 반환, 그중 17개만 캐시 키에 정확히 일치
- 이는 지도 정확도 5%라는 뜻이 아닙니다. 실제 사건 위치 일치 여부는 별도로 검증해야 합니다.

## 검증된 원인

1. 기존 규칙은 제목만 보고 장소를 찾고, 실제 지명 사전을 확인하지 않아 \`반드시\`, \`대학입시\`, \`혁신도시\`, \`특례시\`, \`통합시\`도 도시명처럼 추출할 수 있었습니다.
2. \`하남\`, \`안산\`, \`성북\`, \`강남\`, \`태안\`, \`서산\` 같은 공식 지역명의 축약형을 놓쳤습니다.
3. \`서울\`과 \`서울특별시\`, \`충남\`과 \`충청남도\` 등이 서로 다른 JSON 키로 취급돼 지도 캐시 적중률이 떨어졌습니다.
4. 현재 main의 \`prepare_news_for_frontend(geocode_missing=False)\`는 기존 지역 좌표 캐시를 사용하지 않습니다. PR #16이 이 문제를 수정하고 있으며, 이 PR의 독립 실행 경로에도 호환 캐시 연결을 추가했습니다.
5. \`run_pipeline.py --with-ai --skip-fetch\`에서 오래된 numeric ID가 Gemini 입력에 남아 있으면 URL 해시 ID로 처리한 나머지 단계와 분석 결과가 맞지 않을 수 있었습니다.

## 개선 정책

- **지명은 명시적으로 확인한 행정구역 사전에서만** 추출합니다. 무의미한 \`*시\` 단어를 위치로 처리하지 않습니다.
- 제목에서 두 개 이상의 서로 다른 장소가 나오면 섣불리 하나를 선택하지 않습니다.
- 기자 위치를 나타내는 \`[서울=뉴시스]\` 표기는 사건 위치의 증거로 쓰지 않습니다.
- 지명이 정확하게 확인되지 않으면 좌표를 임의로 만들지 않고 기사 목록에 유지합니다.
- 캐시는 **정확히 일치하는 행정구역 대표 좌표만** 재사용하며, 실제 발생 주소가 아니라는 주의 문구를 유지합니다.
- 이전 지도 파일의 좌표는 현재 기사와 제목이 같더라도 현재 분석에 지역 근거가 없으면 재사용하지 않습니다.
- \`rule_version\`이 바뀌면 과거 규칙 결과를 재분석하되, 수정되지 않은 정상 Gemini 분석 결과는 유지합니다.
- 저장된 옛 숫자 ID를 Gemini 입력으로 넘기기 전에 현재 URL 해시 ID로 정규화합니다.

## 자동 감사 실행

\`\`\`bash
python tools/audit_location_coverage.py --input news_results.json --cache map_visualization/.geocode_cache.json --output test-artifacts/location-audit
\`\`\`

산출물:
- \`summary.json\`: 기존/개선 규칙의 지명 인식 및 캐시 적중 집계
- \`articles.csv\`: **전 기사 1행씩**, 지역명/근거 유형/캐시 적중/이전 인식 결과

CI는 이 감사 보고서를 아티팩트로 업로드하며 외부 API를 호출하지 않습니다.

## 운영·제품 위험과 한계

- **캐시 적중률 ≠ 위치 정확도.** 같은 지역 중심 핀을 여러 기사에 재사용하면 같은 사건 지점처럼 오인할 수 있습니다.
- 뉴스가 전국 단위 정책이거나 사건 장소가 불명확하면 지도에 표시하지 않는 것이 안전합니다.
- 기사 본문은 지역 외에도 여러 장소를 언급할 수 있습니다. 제한적인 문맥 검사를 통과하지 않으면 사용하지 않습니다.
- 전 기사에 대한 독립적인 정답 위치 라벨이 없으므로 precision/recall 수치를 보고할 수 없습니다.
- PR #16과의 **병합 순서 및 CI 재검증**이 필요합니다. PR #16이 지도 JSON과 메타데이터를 개편하므로 최종 통합은 두 PR을 합친 뒤 확인해야 합니다.
- Windows 실기기 렌더링, 장시간 RSS/Nominatim 운용, 기사 원문 지오코딩 의미 정확도는 별도의 검증 작업입니다.
